# 设计：日历日期时间轴视图（Day Timeline）

- 日期：2026-10-18
- 状态：待评审（spec 阶段，尚未进入实现）
- 范围：在现有日历月视图上，点某个日期后打开一块新的「第四象限时间轴」区域；
  为了让时间轴有真实位置，同时给日程补上可选的起止时刻。
- 关联：现有日历月视图、日程解析器、`SCHEDULE_VERSION` 回填机制。

## 1. 背景与目标

现在的日历只精确到「日」：点日期后，下方列的是当天有哪些安排，但看不出
「这件事在一天里的什么时候」。用户要的新视图是：

> 点日历里的某个日期，打开全新 UI。左上角是当前选中日期，下方是只画第四象限的
> 坐标轴：x 轴正方向是时间轴（单位可在小时/半小时间切换），y 轴负方向排事件，
> 一个事件独立一行。只有起始时刻的事件从起始时刻拉到当天 24:00；只有截止时刻的
> 从当天 00:00 拉到截止时刻；起止都没有的，把事件条铺满一整天。

目标：

1. 选中日期后，用一条 00:00–24:00 的横轴把当天每件事画成一根条，位置由时刻决定。
2. 时刻缺失时诚实降级为「全天 / 时刻未识别」，不猜时间。
3. 原有「修改 / 改颜色 / 查看原文 / 改动历史」全部保留，不因新视图回退功能。
4. 旧卡片在下次启动时自动获得时刻，不需要用户手工重录。

## 2. 已确认的决定

用户在 2026-10-18 的方案讨论中确认：

1. **时刻由服务端确定性解析**，前端只负责排版；不采用纯前端正则，也不在本期增加
   手工时刻选择器。
2. **「仅有起始 / 仅有截止」指只有一端时刻**，按统一公式裁剪；不做「没有截止日期
   就一直显示到今天」的无限期事件。
3. **新视图内嵌在日历下方**，不用全屏弹层，也不新增独立路由。
4. **时间轴下方保留现有当天详情列表**，编辑、颜色、原文、历史入口不变。
5. 24 小时横轴可横向滚动；`1 小时 / 30 分钟` 切换只改变刻度与网格密度。

## 3. 非目标（本期不做）

- 拖动事件条改时间、拖拽调整时长。
- 分钟级刻度（最小 30 分钟一格）。
- 跨日事件画成一条弯曲/跨行的长条；仍按选中日裁剪成当天的一段。
- 无限期事件（open-ended）与「从起始日一直显示到今天」。
- 独立 `#/cards/day/...` 路由、全屏弹层、移动端重排。
- 月视图的排版、区间跑道、颜色配置逻辑。
- 用 AI 提取时刻；时刻只走确定性规则。
- 手工时刻选择器（解析错了仍可通过现有编辑表单改 `time` / 原文来纠正）。

## 5. 数据契约

在 `CardSchedule` 上新增两个**可选**字段：

```ts
interface CardSchedule {
  start: string; // YYYY-MM-DD
  end: string;   // YYYY-MM-DD
  /**
   * 起始时刻 HH:mm；文本里没有可靠时刻时为 null / 缺省。
   * 只允许 00:00–23:59；24:00 只允许出现在 endTime。
   */
  startTime?: string | null;
  /** 截止时刻 HH:mm；24:00 合法，表示当天结束 */
  endTime?: string | null;
  // dayCount / label / inferredYear / role 保持不变
}
```

约定：

- 字段可选是为了兼容旧数据和旧前端：缺失 = 「时刻未知」，不是「全天确定事件」。
- 存字符串 `HH:mm` 而不是分钟数：JSON 可读、便于排查；排版时再转分钟。
- `24:00` 只用于 `endTime`；`startTime` 出现 `24:00` 视为非法丢弃。
- 时刻是**本地时间**，不做 UTC 转换；日期本身已经是本地日期。
- `toCardView` 必须显式拷贝这两个字段，并丢弃格式不合法的值。
- 服务端 `DateSchedule`（`date-parser.ts` 内部类型）同步加这两个字段，保证
  `buildSchedules` / `parseSchedule` 的返回值能直接赋给 `CardSchedule`。
- 不新增数据库列；`schedules` / `schedule` 的 JSON 结构自然扩展。

## 6. 时刻解析

### 6.1 解析来源

- 每个日程候选在自己的小句上解析时刻；`toSchedule` 阶段完成，**在按角色合并之前**。
  这样合并后的长 `label` 不会把两件事的时刻混在一起。
- `parseSchedule(timeText)` 这条兜底路径同样解析，用于原文没有日期、只能靠 `time`
  字段排期的卡片。
- 绝不从整段原文里为某一条日程找时刻——那会把别的小句的「办公时间 9:00-17:00」
  挂到截止日上。

### 6.2 认哪些写法

先归一化：全角数字 → 半角、`：` → `:`、中文数字（仅紧挨着「点/时/分」时）。

| 写法 | 结果 |
| --- | --- |
| `14:30` / `14：30` | `14:30` |
| `14:30-17:30` / `14:30至17:30` / `14:30~17:30` | 起止 `14:30`–`17:30` |
| `下午3点` / `下午3点半` / `下午3点30分` | `15:00` / `15:30` / `15:30` |
| `早上8点` / `晚上7点` / `中午1点` / `凌晨12点` | `08:00` / `19:00` / `13:00` / `00:00` |
| `16:00前` | 截止时刻 `16:00` |
| `24:00` | 仅作为 `endTime`，折算 1440 分钟 |
| `15点30分` | `15:30` |
| `三点` / `三点半` | `03:00` / `03:30`（中文数字） |

不认：

- 没有冒号也没有「点/时」的数字，例如 `3-8`、`2026`、`10月22日` 里的数字。
- 越界时刻：`25:00`、`12:60`、`24:30`。
- 只写「上午/下午」但没有具体钟点的文本。

### 6.3 取哪一组时刻

以**日期在句中的位置**为锚：

1. 取日期之后最近的一组连续时刻；日期之后没有，则取日期之前最近的一组。
2. 一组里出现两个及以上时刻时，取最早与最晚构成区间；只有一个时刻时按单时刻处理。
3. 同句出现多组互不相连的时刻时，只取与日期最近的那一组，其余忽略。
4. 解析结果必须落在 0–1440 分钟；越界丢弃整组。

这样「10月22号（第八周周四）14:30-17:30」能拿到 14:30–17:30，
而「9月23日12:30开始报名，9月24日15:00活动」因为已经切成两个小句，
各自只拿到自己的时刻。

### 6.4 角色决定填哪一端

| 角色 | 时刻分配 |
| --- | --- |
| `deadline` | 只填 `endTime` = 该组最晚时刻；`startTime` 保持 `null` |
| `activity` / `visit` | 区间 → `startTime` + `endTime`；单时刻 → 只填 `startTime` |
| `primary` | 同 `activity`；若该小句含「前 / 截止 / 完成 / 提交」等词，按 `deadline` 处理 |

语义解释：

- `deadline` 表示「这天之前要办完」，所以条从 00:00 画到截止时刻。
- `activity` / `visit` 表示「什么时候开始」，只有开始时刻时画到 24:00。
- 两端都没有 → 全天 + 「时刻未识别」。

### 6.5 合并与兜底

- 同一角色内合并两条重叠日程时：`startTime` 取较早的非空值，`endTime` 取较晚的非空值。
- 合并后若 `endTime < startTime`：丢弃 `endTime`，按「只有起始」处理；避免负宽度。
  `endTime === startTime` 保留为点事件，视觉上给最小宽度。
- 解析不出任何时刻：两个字段都留空，界面画全天条并明确标注。
- `time` 字段兜底解析时，若文本含「前 / 截止 / 完成 / 提交」，按 `deadline` 填 `endTime`；
  否则按 `primary` 填 `startTime`。

## 7. 一天内的裁剪与排版

### 7.1 统一裁剪公式

选中日 `D`，日程日期区间 `[start, end]`：

```text
dayStart = (D === start) ? (startTime ?? 00:00) : 00:00
dayEnd   = (D === end)   ? (endTime   ?? 24:00) : 24:00
```

| 情况 | D 上的条 |
| --- | --- |
| 只有 `startTime` | `startTime → 24:00` |
| 只有 `endTime` | `00:00 → endTime` |
| 两者都没有 | `00:00 → 24:00`，标「时刻未识别」 |
| 两者都有 | `startTime → endTime` |
| 多日事件中间日 | `00:00 → 24:00` |
| 多日事件首日 | `startTime ?? 00:00 → 24:00` |
| 多日事件末日 | `00:00 → endTime ?? 24:00` |

防御：

- `D` 不在 `[start, end]` 内 → 不生成条（正常调用不会出现，纯函数要能兜住）。
- 计算出的 `dayEnd < dayStart` → 丢弃结束端，按「只有起始」画到 24:00；
  不把它压成一个点，那会把「17:00–15:00」这种坏数据伪装成瞬间事件。
- 零长度事件（起止分钟相等，如 `12:30–12:30`）保留真实 `start/end` 数据，
  CSS 给 10px 最小可见宽度，不把视觉宽度当成时长。

### 7.2 行与几何

- 一个日程一行，按 `dayStart` 升序；相同时按标题、再按 `scheduleIndex` 稳定排序。
- 行高 48px，条高 26px、垂直居中；与月视图跑道 26px 的视觉厚度一致。
- 时间轴比例固定：`HOUR_WIDTH = 72px`，`PLOT_WIDTH = 24 × 72 = 1728px`。
- 条的横向位置与宽度直接由分钟算：
  `left = startMin / 60 × 72`，`width = (endMin - startMin) / 60 × 72`。
- 单位切换不改变比例与条位置，只改变刻度标签与网格：
  - `1 小时`：每 60 分钟一个刻度，24 个标签，72px 间距。
  - `30 分钟`：每 30 分钟一个刻度，48 个标签，36px 间距；标签字号降到 10px，
    并对齐刻度线。
- 横向滚动；日期表头与单位切换在滚动容器之外，不随横轴移动。
- 初始滚动位置：第一条事件的 `dayStart` 前 60 分钟（72px）；没有事件则停到 07:00。
  日期切换时重新计算。
- 短条（宽度 < 110px）把标题与时间放到条外侧的空白处，避免条内放不下：
  - 默认放右侧；右侧会越过 24:00 时放左侧。
  - 条外侧文字不参与时间定位，不改变条的宽度。
- 长条把角色标签、标题、时间写在条内；标题单行省略，`title` 属性给完整文本。

### 7.3 轴与空态

- 只画第四象限：左上角日期，下方一条向右的 x 轴、一条向下的 y 轴；
  不画负 x、不画正 y、不画四边框。
- x 轴刻度 `00:00` 在最左，`24:00` 在最右；y 轴用行分隔线与每行左侧的小刻度表示。
- 没有事件时仍渲染完整的 00:00–24:00 轴，并显示「这天没有安排。」。
- 轴是装饰性元素，读屏不逐个念刻度；用一段隐藏文字概述「时间轴 0 点到 24 点」。

## 9. 交互

| 操作 | 结果 |
| --- | --- |
| 点日期圆 | 打开该日时间轴；再点同一天收起 |
| 点月视图里的区间 | 跳到区间起始日（跨周段落本周首日），打开时间轴并高亮对应条 |
| 点事件条 | 高亮该条 + 下方对应详情；必要时把详情滚进可视区 |
| 点「收起」 | 关闭时间轴，回到只显示月视图 |
| 切换 `1 小时 / 30 分钟` | 只改刻度与网格；条位置、滚动位置、选中项不变 |
| 键盘 Tab / Enter | 事件条可聚焦、可触发；焦点样式沿用全局 `:focus-visible` |

不持久化单位选择：打开或切换日期时重置为 `1 小时`，避免多一个本地偏好。
日期切换、月份切换时重置选中项（沿用现有行为）。

## 10. 边界与错误处理

- 老数据没有 `startTime/endTime`：全天条 + 「时刻未识别」，不报错、不消失。
- 非法时刻（格式错、越界）：`toCardView` 丢弃该字段，按缺失处理。
- `endTime < startTime`：服务端已丢弃 `endTime`；前端再兜一次，按只有起始处理。
  `endTime === startTime` 是点事件，保留两端。
- 跨午夜事件（23:00–01:00）：MVP 不解析成跨天；若数据出现 `end < start`，按当天
  起始到 24:00 处理，并在条上保留真实时刻文本，避免静默改数。
- 同一天多条同名事件：按 `scheduleIndex` 区分，`data-entry-key` 唯一。
- 事件很多：页面纵向滚动，不做虚拟列表。
- 标题过长：条内省略 + `title`；短条外侧文字最多两行，超出省略。
- 时间轴宽度固定 1728px，窄窗口只横向滚动，不压缩条宽。
- 无 `schedules` 的旧卡：沿用现有 `schedule` 兜底，行为不变。

## 12. 回填、发布与回滚

- `SCHEDULE_VERSION` 从 6 升到 7，并在注释里记一条「7：解析日程的起止时刻」。
- 启动时 `backfillSchedules()` 会自动重算所有 `< 7` 的卡片；不改 `updated_at`、
  `revision_count`，不写改动历史。
- 上线前：
  1. 备份 `data/cards.db`；
  2. 在副本上启动一次，导出所有卡片的 `start/end/schedules` 前后对比；
  3. 确认日期没有意外变化，只有 `startTime/endTime` 新增，再跑真实库。
- 回滚：
  - 前端可单独回滚，旧前端忽略新字段；
  - **回滚解析器不能只把版本号改回 6**：已经按 7 算过的行不会重新计算，会继续停在
    新规则的结果上。要么恢复备份数据库，要么发一个版本号 8、逻辑回退到旧规则；
  - 已写入的时刻字段对旧前端无害，可保留。
  - 若日期被改坏，恢复备份数据库最稳。
- 发布顺序：共享类型 → 服务端解析与回填 → 前端视图。同一分支内提交，最后一起并入。
- 兼容性：新前端 + 旧服务端 = 全部按全天显示；旧前端 + 新服务端 = 忽略时刻，行为不变。

## 13. 验收标准

1. 点日期打开时间轴，左上角显示选中日期；再点同一天收起。
2. x 轴覆盖 `00:00`–`24:00`，可横向滚动查看两端；y 方向一行一个事件。
3. 只有起始时刻 `12:30` → 条为 `12:30–24:00`；只有截止时刻 `15:00` →
   `00:00–15:00`；两者都无 → 全天并标「时刻未识别」；两者都有 → 精确区间。
4. 多日事件首日从起始时刻开始、中间日全天、末日到截止时刻。
5. `1 小时 / 30 分钟` 切换后刻度与网格变化，条位置与选中状态不变。
6. 空日期仍显示坐标轴和「这天没有安排」。
7. 原有修改、颜色、原文、历史入口仍可用；点条能高亮对应详情。
8. `pnpm verify`、`pnpm smoke`、`pnpm verify:ui` 全绿；真实浏览器几何误差 ≤ 2px。
9. 旧卡在启动回填后能在时间轴上有正确位置；没有时刻的旧卡显示全天并标注。

## 14. 风险与取舍

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 时刻解析错位（同句多组时刻、办公时间） | 条的位置误导 | 以日期为锚取最近一组；解析不出就留空；黄金用例覆盖真实通知 |
| 回填旧卡时日期被改动 | 用户日程整体错位 | 备份 + 副本上 diff 前后 `schedules`；只在确认后启动真实库 |
| 24 小时轴太宽 | 需要横向滚动，初看只见半天 | 初始滚到第一条事件；表头固定；单位切换不缩放 |
| 短条放不下标题 | 看不清是什么事 | 条外标签 + `title`；行高与条高保持可点 |
| 现有 60+ 日历测试大面积改动 | 回归风险 | 保留 `calendar-detail` 外壳与详情列表结构，只新增时间轴；逐条补断言 |
| 用户把「只有起始」理解成无限期 | 期望不一致 | 本期明确按「只有一端时刻」实现并写进文档 |
| 沙箱内测试子进程被 EPERM 挡住 | 无法确认全绿 | 交付前用一次提权运行完整验证链路，不以沙箱失败代替测试结论 |
